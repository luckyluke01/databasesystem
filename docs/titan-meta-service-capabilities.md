本文档汇总自《titan能力汇总.pdf》与《meta6200-6300任务拆解.xlsx》（含 6400、事件、元数据梳理、待办等子表），并结合仓库内《MySQL 协议数据库服务对外能力清单与白皮书草案》中与 Query 层相关的表述。  
**Excel 中每条任务在文中尽量映射为一条可独立表述的「能力」**；状态以表内为准：`已完成` / `代码已合并` 视为已提供；`待联调` 单独标注；`延后` / `进行中` / 讨论项在附录说明，不并入「已提供」主清单。

## 第一部分：服务底层原理（PDF + 任务表归纳）

### 1.1 产品本质

- 面向 ONE 观测体系：**指标（多模型）+ 实体实例 + 记录/会话** 等数据，底层以 **ClickHouse（CK）** 为主存储；关系型侧（如 MySQL/MariaDB）承载元数据、账号环境、部分配置与协调逻辑。
- **「模型」（V1～V5 等）** 不是单一表结构，而是一套 **物理模板 + 元数据映射**：同一业务指标在不同版本下对应不同的宽表/星型/ETL 拆维/字典组合等落库方式。
- **统一读写与解耦**：写入与查询主要感知 **业务模型与元数据**；物理表结构、TTL、粒度、套表切换、维度映射时间线等由元数据驱动；目标为 **底层存储可调、上层业务少改或无感**（PDF「数据血缘」）。

### 1.2 存储与计算核心机制（PDF）

| 机制 | 要点 |
| --- | --- |
| **维度字典** | 维度值抽成最多约 4 组维度 ID 入库；titanClient 用位图判重；同中心多节点按维度 ID hash，保证同 ID 一份；高基实体类维度默认留在事实表。 |
| **明细留存** | 由元数据控制是否保留明细（如阈值类场景）；默认 V1（第三方）偏保留明细，V5 默认不留明细等。 |
| **同步/异步写入** | 同步常配合 buffer 表（占内存）；可按元数据改为异步，换资源与实时性。 |
| **套表与隔离** | 用户级或指标级切换存储套表，实现资源隔离、差异化 TTL 与粒度。 |
| **计算方式切换** | 元数据 + 标准底表 DDL 调整 → **双写** → 约定窗口后切查询映射列，上层业务不随列级算法替换而改。 |
| **实体实例下推 CK** | 实例入 CK local（如 ReplacingMergeTree），上叠分布式表与**字典**；查询里 `dictGet` 与 `where in` 分布式表组合；延迟约 10～20 秒及实例规模与内存上限等约束（PDF）。 |
| **记录/会话** | 记录 map→json；会话直写、引擎与聚合类型调整以降资源（SummingMergeTree、SimpleAggregateFunction 等）。 |
| **多中心与两层分布式表** | 明细/粒度/维度/实例等：`all_cluster` 一级分发 → 各 `cluster` 二级；实例类数据可只落主中心；对外查询表名尽量不变。 |
| **元数据扩展** | 覆盖套表集合、TTL、粒度、维度组合映射、指标/维度切换时间线等；调配入口 PDF 写明当前多在 **oneData**。 |

### 1.3 任务表反映的工程闭环（Excel）

- **链路**：指标/实体注册 → 模板建套表（多中心锁、均衡）→ **ingest 写 CK**，失败 **Kafka 回调重试** → MySQL 与 CK 字典/标签表 **双写或定时 reload** → **change_log / changelog** 推送维度与 mapping 变更。
- **典型内部能力名（备注列）**：`createInstanceTagModelAndStorage`、`instanceDataRebalance`、`migrationInstanceTag`、`reloadInstanceAndInstanceTagToCk`、`consumerStorageDictQueue`、`createInstanceTag` 等。

### 1.4 Query / MySQL 协议层（仓库白皮书摘要）

当前系统更接近「统一查询服务 + MySQL 协议接入层 + 多源查询适配层」，而非完整通用 MySQL。对外可表述为：统一查询端点、BQL/PQL、账号与 TLS、模型数据查询、实例与关系联查等；事务、全量 MySQL 语义等不在主能力范围内。详见仓库 `docs/mysql-protocol-database-capability-whitepaper.md`。

## 第三部分：与行业产品的能力矩阵（简表）

| 能力维度 | 本服务（Titan + meta） | ClickHouse 原生 | Snowflake / BigQuery | Doris / StarRocks | 时序/指标栈（如 M3 等） |
| --- | --- | --- | --- | --- | --- |
| 多物理模型（宽表/星型/ETL 拆维） | **强** | 自建 | SQL/表级 | 自建 | 偏单一模型 |
| 维度字典 + 高基/低基治理 | **强** | 自建 | 弱 | 中等 | 部分可比 |
| 元数据驱动套表切换、隔离 | **强** | 无 | 账户/warehouse 级 | 部分类比 | 因产品而异 |
| 算法列切换（双写+时间线） | **强** | 手工 | 视图/新列 | 物化/新表 | 因产品而异 |
| 实体+指标联查优化 | **强** | 自建 | 通用 JOIN | rollup 等 | 非核心 |
| 多中心拓扑 | **有设计** | 自建 | 强 | 需规划 | 因产品而异 |
| 标准 SQL / 事务 | **非主目标** | OLAP 子集 | 强 | 较强 | 各异 |
| 托管弹性 | **部分**（接口+任务化） | 云或自建 | **强** | 中强 | 云产品强 |
